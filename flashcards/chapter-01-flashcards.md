## Chapter 1: Cloud Architecture Design Fundamentals & The Four Case Studies — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | TerramEarth: how many connected vehicles, and how many sensors per vehicle? | ~2 million vehicles; 200-500 sensors per vehicle, generating 120-200 data points per second. Exam tip: this scale signals a streaming/Pub/Sub ingestion answer, not batch. |
| 2 | TerramEarth: current batch upload frequency and volume per vehicle vs. new daily data target? | Currently ~9GB per vehicle uploaded once every 3 months at a dealership. New requirement: ingest ~50TB of new data per day company-wide. Exam tip: the gap between these numbers is the justification for a real-time streaming redesign. |
| 3 | HRL: what availability SLA target is commonly used for the live streaming backend? | 99.99% availability. Exam tip: 99.99% implies multi-region/HA design with redundant VPN or Interconnect and no single points of failure — 99.9% alone is insufficient when this exact figure is stated. |
| 4 | EHR Healthcare: what three connectivity domains must the architecture span? | On-premises data centers, GCP, and an existing AWS environment. Exam tip: any correct EHR answer must preserve hybrid + multi-cloud connectivity, not eliminate one leg of it. |
| 5 | GKE for Mountkirk Games: regional cluster vs. zonal cluster — which fits a global low-latency multiplayer launch? | Regional (multi-zone) GKE clusters deployed across several regions near player populations, fronted by a global load balancer. Zonal clusters are single points of failure and don't address global latency. |
| 6 | HA VPN SLA: what topology is required to qualify for 99.99% availability? | Two tunnels from two interfaces of an HA VPN gateway, connected to two separate peer VPN gateways/tunnels. A single tunnel or single peer never qualifies for the 99.99% SLA. |
| 7 | Business requirement vs. technical requirement — what's the exam distinction? | Business requirements describe WHAT the organization needs (e.g., 'reduce cost', 'expand globally') — usually vague. Technical requirements describe HOW the system must behave (e.g., 'encrypt data at rest', '99.99% SLA') — usually specific and testable. Exam tip: translate vague executive quotes into the specific technical requirement they imply. |
| 8 | PCA trade-off rule: when a stated SLA/HA number conflicts with a 'minimize cost' statement, which wins by default? | The explicit HA/SLA number is treated as a hard constraint; cost statements are optimization goals to pursue within that constraint (e.g., committed use discounts, autoscaling) — not an excuse to violate the SLA. |
| 9 | EHR Healthcare: what two encryption requirements are explicitly stated? | Encrypt data at rest and encrypt data in transit, across on-prem, GCP, and AWS. Exam tip: any answer relying only on network-level security (e.g., private IPs) without explicit encryption fails this requirement. |
| 10 | Pub/Sub vs. Cloud Tasks — which fits high-volume IoT telemetry ingestion? | Pub/Sub — designed for massive-scale, high-throughput, decoupled event ingestion (e.g., TerramEarth vehicle telemetry). Cloud Tasks is for reliable execution of discrete, individually-managed application tasks, not continuous sensor streams. |
| 11 | RTO vs. RPO — quick definition for exam scenarios | RTO (Recovery Time Objective) = how long until service is restored after failure. RPO (Recovery Point Objective) = how much data (in time) you can afford to lose. Exam tip: a case study statement like 'resume in X minutes, lose no more than Y seconds of data' maps directly to RTO=X, RPO=Y. |
| 12 | Quick ID trick: how to recognize each of the 4 PCA case studies from a single keyword in the question | EHR Healthcare = hybrid/on-prem + compliance + healthcare SaaS. HRL = live video streaming + global spectators + ML race predictions. Mountkirk Games = mobile multiplayer + GKE + real-time analytics. TerramEarth = IoT/vehicle sensors + massive telemetry + predictive maintenance. |
