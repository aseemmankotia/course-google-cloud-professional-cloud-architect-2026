## Chapter 4: Infrastructure as Code & Automated Provisioning — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Terraform GCS backend — how is state locking achieved? | Via a lock file object in the GCS bucket, using generation-number compare-and-swap (no separate lock table needed, unlike AWS S3+DynamoDB). Exam tip: always enable object versioning on the state bucket for recovery. |
| 2 | Max service projects attachable to one Shared VPC host project? | Up to 100 service projects per host project. Exam tip: the host project owns the VPC; service projects consume subnets via the Network User role. |
| 3 | Cloud Build default timeout vs max configurable timeout? | Default: 600 seconds (10 min). Max: 86400 seconds (24 hours), set via the 'timeout' field in cloudbuild.yaml. Exam tip: raise this for long terraform plan/apply steps. |
| 4 | VPC firewall rule priority range vs hierarchical firewall policy priority range? | VPC firewall rules: 0–65535 (lower number = higher priority). Hierarchical firewall policies: 0–2147483647. Exam tip: hierarchical rules are evaluated before VPC-level rules unless 'goto_next' is used. |
| 5 | Config Connector — Namespaced mode vs Cluster mode? | Namespaced mode: one GCP project mapped per Kubernetes namespace (multi-tenant). Cluster mode: single default GCP project for the whole cluster. Exam tip: namespaced mode is recommended for multi-team resource management. |
| 6 | Terraform vs Deployment Manager — language and scope? | Terraform: HCL, multi-cloud, state file in a self-managed backend. Deployment Manager: YAML/Jinja2/Python, GCP-only, state managed internally by Google. Exam tip: Google steers new projects toward Terraform/Config Connector; DM is in maintenance mode. |
| 7 | What does Private Google Access enable? | VMs without external IPs can reach Google APIs/services (e.g., Cloud Storage, BigQuery) via internal IP. Configured per-subnet. Exam tip: it does NOT provide general internet access — that's Cloud NAT's role. |
| 8 | Cloud NAT — default minimum ports allocated per VM instance? | 64 ports per VM by default (configurable min/max). Cloud NAT is regional and requires a Cloud Router in the same region/network. Exam tip: provides egress-only NAT — no unsolicited inbound connections. |
| 9 | Which IAM role lets a Shared VPC service project use a specific subnet? | roles/compute.networkUser, granted at the subnet or project level. Exam tip: roles/compute.xpnAdmin (Shared VPC Admin) is granted at org/folder level to enable Shared VPC itself. |
| 10 | Terraform module vs workspace — key distinction? | Module = reusable, parameterized resource configuration (like a function). Workspace = separate named state instance for the same configuration (e.g., dev, staging, prod). Exam tip: workspaces isolate state, not code. |
| 11 | Which GCP-native tool manages GCP resources as Kubernetes CRDs for GitOps-style infra management? | Config Connector (KCC). Exam tip: runs as a GKE add-on or standalone operator, translating CRD specs into GCP API calls and continuously reconciling drift. |
| 12 | Cloud Build trigger types tested on the exam? | Push to branch, pull request, tag push, manual invocation, Pub/Sub message, webhook. Exam tip: use Pub/Sub triggers to chain builds across projects/pipelines (e.g., trigger terraform apply after an image build). |
